## Inventory Item Creation Process

Inventory items are master records for stock and purchasing. A valid item requires:

- `name`: human-readable item name.
- `sku`: unique per organization.
- `quantity`: opening on-hand quantity.
- `price`: reporting/sales value used in reports.

Useful optional fields:

- `cost`: internal acquisition cost.
- `lowStockThreshold`: reorder/low-stock signal.
- `categoryId`: reporting/category filter.
- `location`: starting warehouse/bin/location label.
- `unitOfMeasure`: default unit label such as `each`, `box`, or `kg`.

Process:

1. User opens `Inventory`.
2. User selects `Add item`.
3. Client validates required fields and posts to `POST /api/inventory`.
4. Server validates with `inventoryItemFormSchema`, which coerces numeric form values.
5. Server checks the subscription SKU limit.
6. Server checks duplicate SKU within the active organization.
7. Server creates the item through storage/repository with active organization scope.
8. Client refreshes the inventory list.

Prior issue:

- The inventory page did not expose item creation.
- The server used the raw insert schema, which is stricter than browser form payloads and can reject numeric strings.
- The create route required `inventory:update`; creation now uses `inventory:create`.

## Export And Custom Report Flow

Reports are organized around an export dataset registry:

- Registry defines dataset key, label, section, formats, columns, join hints, and preview support.
- Export Center can preview report rows before download.
- Custom composite report currently supports `PO vs deliveries`, joining purchase orders, suppliers, and shipments.
- Compressed custom exports use CSV.GZ to reduce file size and lower corruption risk for large downloads.
- Export jobs generated by the background worker are stored as compressed `.gz` artifacts.

## Current High-Risk Data Connections

| Risk | Cause | Mitigation |
| --- | --- | --- |
| Supplier defaults do not appear everywhere | duplicate or bypassed default logic | use `server/modules/procurement/supplier-defaults.ts` as source of truth |
| Master Data changes do not refresh dependent screens | mixed query keys and partial invalidation | use canonical `qk` keys and domain invalidation helpers |
| Inventory create fails | missing UI flow, raw server validation, wrong permission action | add create dialog, use form schema, require `inventory:create` |
| Reports miss cross-module context | single dataset exports only | add registry metadata and composite report endpoints |
| Large export corruption | large raw files downloaded/stored directly | store/download compressed export artifacts |
| Logistics/AP mismatch | shipments and receipt evidence do not always link cleanly to PO/AP | diagnostics should flag orphan shipments and missing AP receipt evidence |

## Testing Priorities

1. Create inventory item from `Inventory`.
2. Confirm duplicate SKU returns a visible 409 error.
3. Preview `PO vs deliveries` in Export Center.
4. Download compressed custom CSV.GZ and open after decompression.
5. Run `npm run check`.
6. Run `npm run build`.
7. Run focused export and inventory API smoke tests where server/database are available.
