# Decisions

- Build 2 closeout: the existing v2 and compatibility approval URLs use the same locked command. The current actor and effective permission determine authority; approval levels and policy versions belong to one submission cycle. Budget reservation and outcome inbox work happen only with the governed transition. Unbound compatibility history is not credited toward a new approval.
- Build 2 closeout: the immutable PO budget reference is prospective. Bind the exact tenant, requisition, approval time and captured exception revision only in governed conversion transactions. The Maverick report never borrows evidence from a current requisition or reconstructs a missing reference. The migration requires separate business approval.

- Build 2: Action Inbox reads the latest assigned obligation version rather than emitting a synthetic reminder. Reassignment removes old work; completed/cancelled latest versions belong in History. An exact agreement/obligation URL is navigation only and never substitutes for current purchase and warehouse scope.

- Build 2: Maverick Spend distinguishes recorded evidence, unverified evidence, and no linked source for each evidence family. “No source linked” is not a compliance decision. The Unverified filter matches any missing applicable evidence, or one selected family; the report retains one ordered-value contribution per PO. Date scope uses inclusive PO issue dates and supplier scope requires current supplier read access and tenant ownership. No history is classified using today's policy.
- Build 2: Contract obligation due dates are stored calendar dates. Compute overdue against the organization's current local day, using the same transaction-clock and timezone validation as AP Aging. An unset timezone defaults to Africa/Johannesburg; an invalid one reports setup required. No saved dates or versions are rewritten.

- Build 2: Linked RFQ draft withdrawal is a sourcing command, not a fresh approval or a data repair. The creation audit records a fingerprint of the locked requisition and lines and the independent approval it matched. Recovery compares these under lock and preserves the RFQ, invitation rows, original approval and existing reservations. Older drafts without captured proof remain blocked. Supplier users cannot open or add clarifications to unpublished or cancelled RFQs. Buyer clarification and withdrawal serialize on the event.

- 2026-11-13 Build 2: A linked RFQ draft consumes the approved requisition's conversion path in the same transaction that creates its auditable draft. Both linked entry points follow this rule; the canonical sourcing form still allows explicitly prepared RFQ lines, while the v2 conversion takes the locked requisition lines and currency. Standalone RFQs do not change a requisition. Draft creation never delivers invitations or places an order.
- 2026-11-13 AP release verification: AP Aging is a normal supplier/Control Tower/Analytics dependency. The disposable runner always installs and verifies the existing AP History migration before fixtures, regardless of selected specs. The business migration remains a separately approved operation; no application-startup or health-check migration. AP Aging failures retain a request ID and sanitized error classification, not source records or SQL.
- 2026-11-13 Build 2: Award approval and PO conversion must commit with their existing audit and retry records. A linked single-PO award carries the original budget reservation to the PO without repricing it. Where multiple suppliers would create multiple POs and an active requisition reservation exists, stop for Finance review rather than assign all of it arbitrarily, divide it, or convert currency. Unreserved awards retain existing split conversion. Old approvals must have matching audit evidence; no retroactive audit event is synthesized.
- 2026-11-13 Build 2: Agreement release now moves an existing requisition budget reservation unchanged to a linked PO commitment, using the same helper as direct conversion. This conserves approved budget capacity; the reservation remains on its original amount/currency basis and is not the agreement release price. Do not infer a historical transfer on releases that lack this snapshot. Generic supplier commands, including compatibility storage, never accept governed banking fields.
- 2026-11-12 Build 2: The canonical requisition conversion records the actual configured sourcing decision and observed supplier state in the existing audit ledger, atomically with the PO, actor, commitment transfer and retry key. The report distinguishes it from PO submission or agreement-release evidence. The PostgreSQL compatibility mapper shares the transaction-aware line writer but does not certify unrecorded policy decisions. Do not infer that absent evidence, or absent catalogue, agreement or preferred-supplier use, is a policy breach.
- 2026-11-09 Build 2: Obligations attach to the existing tenant-owned contract; changes append audited versions. This does not change commercial terms, approvals or renewal rules. Completion needs the assigned active owner and a verified version of a contract document. Historical evidence prevents deleting the parent contract; use its close workflow.
- 2026-11-09 Build 2: Budget-policy evidence is captured at canonical budget-controlled requisition approval; no backfill or applying current settings retrospectively. An independently approved sourcing override requires exact same-tenant award approval and PO conversion audit evidence and does not waive budget policy. Unverified history is not compliance. Reuse one canonical ordered-value contribution per PO and preserve its original currency without summing unlike currencies.

- 2026-11-02: Use the user's ten-capability dependency order in PROGRAM.md. Do not replace canonical systems.
- Missing programme-control files were created from explicit user requirements and audited source, not recovered or assumed earlier decisions.
- Supplier 360 extends `client/src/pages/supplier-detail.tsx`; contacts, communications, financial measures and AP aging remain canonical components.
- The first Supplier 360 slice is a read-only dated delivery observation. It uses approved PO source-state definitions and posted receipts with accepted quantity. First accepted receipt is not full delivery or an OTIF measure.
- The period is the PO order-date cohort, using the existing timestamp-without-timezone date convention. It is not an as-of query. Current PO promises/statuses may have changed; no historical promise or immutable scorecard is inferred.
- Organization-wide delivery observations require suppliers/read, purchases/read, inventory/read and an active unrestricted-warehouse membership. Restricted actors receive an explicit denial, not a misleading partial company score.
- This slice introduces no financial totals, new ledger, provider, migration or business mutation. Missing evidence is not perfect performance. Financial panels continue to use the shared financial-measure services.
- Combined legacy ratings include invoice-dispute evidence, so they require Finance read access in addition to supplier, purchase and inventory access. The pure delivery observation does not require Finance. Both use active membership and unrestricted warehouse evidence; client gating is guidance only.
- The legacy performance URL is retained with the same array body for explicit bounded IDs. Unbounded legacy calls now return actionable 400/deprecation guidance; production UI already supplies visible IDs. No arbitrary first-N subset or broad in-memory scan is allowed. Legacy rating methodology remains a labeled proxy, not a newly verified historical/compliance measure.
- Live query cache identity includes the active session organization, actor and warehouse assignment. Canonical invalidation refreshes live delivery observations but must not invalidate saved financial evidence.
- 2026-11-03 source audit: general supplier list/detail responses and the single-supplier PDF layout exposed legacy banking fields. Client uses were limited to supplier-form defaults already omitted on save; controlled bank changes/read views already belong to Supplier Banks in Master Data. General profile DTOs/new exports therefore omit bank name/account/SWIFT for every role, including administrators/internal export transport. No fake masked value, bank-data rewrite or new bank-read/approval system. Internal repositories and immutable historical evidence remain unchanged. Previously generated retained files require a separate current-access/provenance audit; this slice does not rewrite/delete them.
- 2026-11-03 retained-file audit: standard export jobs lacked disclosure-policy/hash provenance. New supplier files must receive a server-generated `supplier-profile-no-banking-v1` generation header, then publish exact packaged-byte SHA-256/size/path evidence atomically with job success and the existing audit ledger. No certification based on client filters, active source records, timestamps or filenames. Old unverifiable files stay in history but download/token renewal is refused with regeneration guidance. No legacy backfill, deletion, altered frozen evidence or new export/inbox system. The additive supplier-export publication migration is a separate approval group; prior local migration approvals do not authorize it.
- Retained export bytes must never be public development assets. Refuse direct `/uploads/.../exports/...` access, including one-decoded URI/case/Windows path aliases, before development/test static serving. Preserve other public assets for compatibility; document-source authorization remains a distinct pending slice. Production continues its existing blanket refusal of direct uploads. Do not substitute a filename-only guard or enable Compact exports as part of this fix.
- Document source audit: require canonical document read plus the linked source permission/tenant ownership before metadata, counts or download. Company-wide scope remains unverified for warehouse-assigned actors, including admins. Supplier timelines count only authorized procurement/document sources and omit archived attachments. Portal identities require supplier/user access, active membership and bounded rows. No standalone document register.
- A legacy metadata path is not verified file ownership. Preserve it as unverified history; do not backfill approval or hashes. New authorized uploads bind source identity, file hash/size/path and metadata to the existing append-only audit ledger in the same transaction. Downloads recheck current access and the exact open file; arbitrary path registration refuses without mutation. Direct stored-document static paths are private in every profile. Reattachment uses the existing upload/version workflow.
- Retention audit found the legacy bulk command lacked an organization predicate. Keep it explicit/manual, but constrain archives to the current tenant and authorized owned sources, serialize concurrent calls, and commit the canonical audit with the archive. Never delete files or apply retention automatically from Diagnostics. The existing global policy definitions do not grant cross-tenant access.
- 2026-11-04 document navigation: exact document IDs extend the existing list contract, combined with tenant/source predicates before counts. A URL is a navigation reference, not authorization. Client/server share strict ID/filter/page validation; invalid or ambiguous URLs must not load broader evidence. Source/document links include archive review explicitly, preserving history rather than relabeling an archived record active.
- Supplier attachment choices use server-side available/active filtering before bounded pagination, not the first 100 metadata rows filtered afterward. A previously explicit choice remains pinned across search/pages; failed access checks hide its label and block submission until retry or explicit clearing. No automatic replacement, silent attachment loss or separate document register. Server note creation still revalidates ownership/access/lifecycle in its existing governed transaction.
- Analytics performance remediation reuses the canonical set-wise shipment-candidate join, preserving current tenant/canonical-ID/global legacy ambiguity semantics. No new ownership inference, index, concurrency change, financial measure or larger timeout. Full supplier-risk/unrated/late counts precede bounded attention rows; a top-100 list cannot be an authoritative total. Zero known high-risk signals is neutral, not clearance of unknown ratings. ISO activity dates are projected explicitly instead of truncating a JavaScript Date string.
- Slow Analytics stage evidence is server-side only and bounded to known source/state/duration/row-count fields. No SQL, parameters, credentials, source records or client-controlled ownership are added to ordinary API responses. Runner evidence uses its existing allowlist and request correlation; skipped/denied/failed sources are not reported as successful execution.
- Document runtime fault injection must leave the child command failed, forward async errors through an HTTP boundary and attempt every cleanup stage. A hard-stopped child cannot claim its own finally ran. Parent rescue requires exact guarded database identity plus matching run tokens in the database and a contained, non-linked upload root; mismatched proof must refuse. Controlled dependency rejection is not a claim of real PostgreSQL-outage recovery or protection against machine termination.
- Supplier carrier synchronization remains the existing operational projection used by create/update/approval. A non-carrier without a linked carrier must not invent a carrier or dereference an absent row. Extracting and testing this projection does not certify independent onboarding approval, atomic supplier/carrier/audit writes or dated compliance history; those remain a separate governed slice.
